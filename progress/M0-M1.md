## Source

The Weft design document, draft 0.1, dated 2026-09-02. Converted to
`docs/design.md`. The normative protocol lives in `docs/protocol.md`.

## Review findings folded into the design

- Manifest and pointer chicken-and-egg. A device-signed pointer could point
  a reader at a stale manifest that still authorizes a stolen device.
  Resolution: manifests and the pointer named `manifest` are root-signed
  only. Readers reject any record whose signer is revoked in the newest
  manifest they hold.
- Pointer sequencing. Two devices writing offline fork silently under a
  single per-identity counter. Resolution: Lamport sequence per pointer
  name, each pointer cites the heads it saw, ties broken by created time
  then by address bytes. Forks are visible and mergeable.
- Address format. Bare base32 has no algorithm agility and no typo
  detection. Resolution: one version byte, 32 byte payload, 4 byte blake3
  checksum, lowercase base32 without padding.
- Canonicalization. "Deterministic CBOR" is underspecified. Resolution:
  RFC 8949 core deterministic encoding, restricted to the subset the
  protocol needs, with the rules and test vectors frozen in the spec.
- Grants only bite if the store is a gate. Recorded for M5: the store is
  a daemon reached over IPC, the browser is its only privileged client.
- iroh scope. Build pointers and records on iroh-blobs and iroh-gossip,
  not iroh-docs. Recorded for M2.
- HTML rendering. M3 renders a restricted native subset first. Recorded.
- License versus selling later. Deferred; repo stays private until M3.

## Decisions

| Topic | Decision |
|---|---|
| Name | weft |
| Repo | private, github.com/akrvs/weft, one Rust workspace |
| License | deferred until public |
| First target | M0 spec and vectors, M1 core crate and CLI, no network |
| Signatures | Ed25519 |
| Hash | blake3 |
| Encoding | RFC 8949 core deterministic CBOR, protocol subset |
| Manifest | root-signed only; device keys sign content and other pointers |
| Pointers | Lamport sequence per name, cites prior heads, deterministic tie-break |
| Addresses | version byte, payload, 4 byte checksum, base32 lowercase |
| Docs | docs/design.md context, docs/protocol.md normative |
| Style | no emojis, no code comments, no AI attribution in git |

## Plan

1. Repo skeleton. Workspace, gamified README, toolchain pin, rustfmt,
   clippy denies, cargo-deny, gitignore. Private GitHub repo, first push.
2. M0. `docs/protocol.md` defines record envelope and field order,
   canonical form, address format, manifest and pointer kinds, signing,
   verification, revocation. `docs/design.md` is the converted design
   document. `vectors/` holds fixtures: keys, canonical bytes, hashes,
   addresses, valid and broken records.
3. M1 crate `weft-core`. Modules: address, cbor, identity, record,
   manifest, pointer, verify. Dependencies: ed25519-dalek, blake3,
   data-encoding, zeroize. No async, no I/O, no unsafe. One verification
   choke point. Tests driven from the fixtures.
4. M1 crate `weft`. CLI over the core crate: identity create, device add
   and revoke, manifest publish, sign, verify, pointer set, resolve,
   inspect. Keys at rest encrypted with Argon2id and XChaCha20-Poly1305.
   Demo: sign on one machine, copy files, verify on another.
5. Ops. GitHub Actions: fmt, clippy with warnings denied, tests,
   cargo-deny, fixture conformance. Branch protection on main.

## Out of scope for this pass

iroh, relays, DNS bridge, personal store, browser. The record format
reserves what they need so none of them force a format change.

## Delivered

- `docs/protocol.md` normative spec, `docs/design.md` context.
- `vectors/` four fixture files generated by `cargo run -p weft-core --example vectors`.
- `weft-core`: address, cbor, identity, record, manifest, pointer, verify.
  Zero unsafe, no I/O, no randomness, four direct dependencies.
- `weft` CLI: init, whoami, device add and revoke, manifest, sign, point,
  verify, inspect, resolve. Keys encrypted with Argon2id 64 MiB, t 3, and
  XChaCha20-Poly1305, AAD over the key file header, mode 0600.
- Tests: 3 cbor, 8 protocol, 4 vector, 2 end to end. 17 total.
- CI: fmt, clippy with warnings denied, tests, release build, vector
  regeneration diff, cargo-deny.

## Deviations from the plan

- Devices and revoked lists must be sorted and unique so a manifest has
  one encoding per meaning. Not in the original plan, added during spec.
- Revocation is retroactive. Discovered during the demo: revoking the
  laptop also invalidates the `home` pointer it signed. Kept for version 1
  and recorded as an open question for M2.
- Pointer sequence is per author and name rather than per device. The
  signer field already identifies the device, so a separate field was
  redundant.
