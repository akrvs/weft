# M13

Status: complete, smoke tested on Linux with the real binaries
Started: 2026-09-08

## Goal

Fetch hardening. Close what M12 left open: a public gateway is no longer a
fetch proxy for its relay list, a crashed pull no longer leaves a part
file behind, and a domain with no usable `_weft` record no longer costs a
DoH round trip on every navigation. The demo: an anonymous reader asks
the gateway for a blob its store lacks and gets 404; the same reader logs
in, asks again, and the gateway pulls it; a `.part` left by a killed pull
is gone after the daemon restarts; a bad domain twice hits Cloudflare once.

## Decisions

| Topic | Decision |
|---|---|
| Who pulls through the gateway | Only a request carrying a valid session cookie. Anonymous requests read the store alone: a missing record, head, or blob is 404 with `log in to fetch from relays`, never a relay round trip. A gateway wide cap of 4 pulls in flight; a logged in request past the cap is 429 |
| Where the choke point is | `Resolver::relays` returns the client and the home relay list, or nothing. Every relay round trip in the resolver goes through it. `Resolver::offline` is a cheap handle over the same home, reads, client, and DNS with the list turned off |
| Part sweep | `Store::sweep_parts(older_than)` removes `blobs/*.part` by mtime. `serve` calls it with no age before it binds the socket, since no pull survives a restart. `Store::snapshot` calls it with `PART_TTL`, 120 s, the blob pull timeout, on every listing |
| Negative DNS | The cache holds `Result<Binding, Negative>`. `Negative::NoRecord` for NXDomain or an empty answer, `Negative::Binding(why)` for more than one `_weft` TXT or a malformed value. TTL is the response's SOA negative TTL clamped 60 s to 3600 s, 60 s when absent. Any other response code and every transport failure is an error and is not cached |
| Dependencies | Nothing new. `tokio::sync::Semaphore` for the pull cap; `iroh` and `weft-net` as gateway dev dependencies for the relay in its tests |

## Plan

1. Part sweep: `Store::part_path`, `sweep_parts`, `snapshot` sweeps stale
   parts, `Gate::keep_blob` uses `part_path`, `serve` sweeps all before
   bind. Tests: an old part goes, a fresh part stays, no age removes all,
   a blob file is never touched.
2. Resolver: `Shared` behind an `Arc`, `offline()`, `relays()` as the one
   relay list source, client bound only when the list is non empty.
   Test over the loopback relay: offline misses a blob and a record the
   online resolver then pulls.
3. DNS: `Negative`, cache stores `Result`, negative TTL, `parse` maps a
   bad address to `Binding`. Tests: negative hit within TTL, miss after,
   the absent SOA floor, positive entries unchanged.
4. Gateway: session lookup in `handle`, offline resolver for anonymous,
   semaphore for logged in, 429 text, 404 hint. Tests: anonymous blob and
   page miss are 404 with a relay holding the data, logged in pulls it,
   a full semaphore answers 429.
5. Docs, README, smoke test with the real binaries, close.

## Delivered

- `Store::sweep_parts` and `Store::part_path`; `snapshot` sweeps parts
  older than `PART_TTL`; `weft-store serve` sweeps every part before it
  binds. `PART` and `PART_TTL` live in `weft-home`, and the resolver's
  `BLOB_TIMEOUT` is that constant.
- `Resolver` holds its home, reads, client, and DNS behind an `Arc`;
  `offline()` shares them with pulls off; `relays()` is the only place a
  relay list is read and the client bound.
- `Dns` caches `Negative::NoRecord` and `Negative::Binding` outcomes for
  the SOA negative TTL under the 60 s to 3600 s clamp. `parse` returns
  `Outcome` and never a core error.
- Gateway: anonymous GET and HEAD use the offline resolver and answer 404
  with `log in to fetch from relays`; a live session uses the pulling
  resolver under a `Semaphore` of `MAX_PULLS`, 4, and answers 429 `too many
  fetches in flight` past it. `Gateway::pull_cap` sets the cap.
- Tests: part sweep, offline resolver over the loopback relay, negative
  cache, gateway pull gated by session over a loopback relay, cap at 0.
  91 tests.
- Smoke tested with the debug binaries: relay, publisher home, reader
  home with daemon and gateway. A `.part` planted before `serve` was gone
  after it. Anonymous blob, named, and address requests answered 404 with
  the hint and wrote nothing. Login through the gateway with `weft login
  sign`, the same requests answered 200, the blob matched byte for byte
  and sat in the reader's `blobs/`. Relay stopped, anonymous requests
  answered 200. A domain with no `_weft` record: first request 24 ms,
  the next four under 0.3 ms.

## Deviations from the plan

- hickory 0.26 delivers NXDomain and an empty NoError answer as a
  `NoRecordsFound` error, not as a response, so the negative path matches
  that error and reads its `negative_ttl`. The response path is kept for
  the case where a response does arrive. Found in the smoke test, not the
  unit tests, which drive the cache alone.
- `Gateway::pull_cap` was added so the cap is testable without four
  120 s pulls in flight; the cap test runs at 0.
- The reader home in the smoke test had to move to `/tmp/w13`: the
  scratchpad path put `store.sock` past `SUN_LEN`.

## Open for M14

- The pull cap is gateway wide and per request, not per session or per
  byte. One session can hold all four permits.
- The cap is a constant; the binary has no flag for it.
- The negative DNS path is verified only end to end against Cloudflare,
  not by a unit test with a fake name server.

## Out of scope

- Progress display while a blob downloads.
- Per session byte budgets.
- Gateway allow list reload, session sweep.
