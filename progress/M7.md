# M7

Status: in progress
Started: 2026-09-06

## Goal

Pay a relay a few cents to host a page. A bank key mints signed vouchers,
a payer signs a receipt record that spends one voucher to pin named
records on one relay until a date, and the relay stores paid records from
authors who are not on its allowlist, sweeps them when the pin expires,
and never signs anything. The demo from the roadmap: mint a voucher, push
a page with it, watch the relay serve it, watch it disappear when the pin
runs out.

## Decisions

| Topic | Decision |
|---|---|
| Rail | Signed vouchers from a bank key. No Lightning, no ecash. The rail is one struct behind one check so a real rail can replace it later |
| Voucher | Canonical map `bank` bytes(32), `cents` uint at least 1, `nonce` bytes(32), `sig` bytes(64), `to` bytes(32) relay endpoint key. `sig` is Ed25519 over `"weft/voucher/1" \|\| 0x00 \|\| canonical(map without sig)`. Encoded size at most 256 bytes. Id is the hash address of the encoded bytes |
| Receipt record | `kind = "receipt"`, reserved. Body: `relay` bytes(32), `records` array of 1 to 64 hash addresses sorted unique and all present in `refs`, `until` uint greater than `created`, `voucher` bytes decoding to a voucher whose `to` equals `relay`. Root or device signed. `verify` parses it like every other reserved kind |
| Price | The relay publishes `rate` in cents per KiB per day and the bank keys it accepts. Cost of a receipt is the sum over its records of `ceil(size / 1024) * days * rate`, size being record bytes plus blob bytes, `days = ceil((until - now) / 86400)` on the relay clock. `until` must be in the future and at most 366 days ahead. `cents >= cost`, no change given |
| Put | Batch order: manifests, then other records, then receipts. Records by allowlisted authors store as before. Records and manifests by anyone else are held pending until a receipt in the same batch covers them. A receipt names records that are pending or already stored, is verified, its voucher checked against `to`, the bank set, the spent set, and the cost, then the voucher is marked spent and everything it covers is stored and pinned. Pending records no receipt covered are rejected with `payment required`. A receipt for an already stored record extends its pin |
| Free tier | Allowlisted authors pay nothing and are never swept. Receipts by them are accepted and ignored for storage |
| Sweep | Pins live in the index. Every 60 seconds and at start the relay drops records whose pin has passed, heads that point at dropped records, and manifests of non allowlisted authors with no pin left. Spent voucher ids are kept forever |
| Wire | New request `price {}` and response `price { rate, banks }`. ALPN stays `weft/relay/1`; the request is additive and old relays answer `unknown request type` |
| Relay operator | `weft-relay rate <cents>` writes `rate`, `weft-relay bank add\|remove <address>` writes `banks`, `weft-relay price` prints both. Read at start like the allowlist |
| Bank | New crate `weft-bank`, binary `weft-bank`: `init` makes a 0600 key under `WEFT_BANK_DIR` or `XDG_DATA_HOME/weft-bank`, `whoami` prints the bank address, `mint --to <relay> --cents <n> --out <file>` writes a voucher file mode 0600 with `create_new`. It is a faucet with no ledger |
| CLI | `weft price` asks every configured relay. `weft push <addresses> --pay <voucher> --days <n> [--as <signer>]` signs a receipt covering the addresses, keeps it in the store, and pushes the batch to the voucher's relay only. `weft receipts` lists local receipts. `weft inspect` prints receipt bodies |
| Surface | CLI only. Browser untouched |
| Vectors | `vectors/receipts.json` with valid and rejected vouchers and receipts. Regenerated by the existing example, checked by CI |
| Dependencies | None new |

## Plan

1. Core: `receipt.rs` with `Voucher` and `Receipt`, reserved kind, verify branch, unit tests with a negative for every rule, vectors.
2. Net: `Price` on the wire, `Pricing` in `Relay::open`, pending batch and settle in `put`, pins and spent set in the index, `sweep(now)`, `Client::price`.
3. Net tests: unpaid rejected, paid stored and served, underpaid rejected with the cost, wrong relay, unknown bank, double spend, pin extension, allowlisted free, sweep drops record head and manifest, price request.
4. Relay binary: `rate`, `bank add`, `bank remove`, `price`, sweep loop in `serve`.
5. Bank binary: `init`, `whoami`, `mint`.
6. CLI: `price`, `push --pay --days --as`, `receipts`, `inspect`.
7. Docs: protocol section 11, relay protocol additions.
8. Smoke test the real binaries: bank, relay with a rate, push a page by a stranger without payment, then with, fetch it, wait for the sweep with a one minute pin, fetch fails.
9. Close: M7 file, handoff, backlog, README, verify, CI, land.

## Out of scope

- Real money rails, Lightning, ecash. The voucher trait boundary is the seam.
- Sponsorship: only the pusher pays for their own records.
- Blob garbage collection in the iroh-blobs store if its API makes it more than a call.
- Browser price and pay affordances.
- Relay ledgers, refunds, receipts signed by the relay.
