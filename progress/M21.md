# M21

Status: complete, smoke driven end to end on Linux with the release binaries
Started: 2026-09-15

## Goal

Empty the backlog of everything this machine can close. A Lightning
preimage becomes the second rail behind `Relay::settle`: the relay issues
an invoice over the wire, the payer pays it with any wallet, and the
receipt carries the preimage instead of a voucher. The browser reads the
desktop portal's colour scheme itself, so the light theme renders on
WebKitGTK and both themes get screenshotted. The driven smoke test covers
the login consent dialog against a real gateway, and a test fails CI when
the UI sources drift past the screenshots.

## Decisions

| Topic | Decision |
|---|---|
| Rail | Lightning preimage next to the voucher. A receipt body carries exactly one of `voucher: bytes` or `preimage: bytes(32)`; both or neither is a parse error. The payment id is the voucher id or the hash address of `sha256(preimage)`, spent once through the same `spent` table |
| Invoice wire | `invoice { cents: uint }` answered by `invoice { bolt11: text, hash: bytes(32), expires: uint }`. `cents` 1 to 1 000 000 000, `bolt11` at most 4 KiB. A relay with no node answers `error`. `price` gains `sats: uint`, the relay's sats per cent, 0 when it takes no Lightning; the CBOR subset has no boolean. The relay remembers `hash -> (cents, expires)` in a new `invoices` table, at most 4096 open, for `INVOICE_TTL` 3600 s; the sweep drops expired ones |
| Settle | For a preimage: `sha256(preimage)` must be an open, unexpired invoice whose `cents` cover the recomputed cost; settlement removes the invoice and marks the id spent in the same commit. No node call at settle time. The voucher path is untouched |
| Units | Pricing stays in cents. `Pricing.sats` is the relay's sats per cent, set by `weft-relay sats <n>`, 0 means no Lightning; the invoice amount is `cents * sats * 1000` msat. Reloads on SIGHUP with the rest of the config |
| Node | Trait `Node` in `weft-net`: `invoice(msat, expiry) -> Invoice { bolt11, hash }`. `Fake` in `weft-net` mints a random preimage, answers `bolt11 = "fake" + hex(hash)`, and writes the preimage hex to `<dir>/preimages/<hex hash>` mode 0600 with `create_new`; tests and `smoke.sh` pay by reading that file. `Lnd` in `weft-relay` posts to `<url>/v1/invoices` with the `Grpc-Metadata-macaroon` header, the macaroon from `<dir>/lnd.macaroon` and the TLS certificate from `<dir>/lnd.pem`, built in roots off. `weft-relay node fake` or `node lnd <url>` writes `<dir>/node`; read at start only. The LND adapter ships unverified against a live node |
| CLI | `weft invoice <addresses> --days N [--relay <id>]` computes the cost from local sizes and the relay's rate, prints `bolt11`, hash, cents, expiry. `weft push <addresses> --preimage <hex> --days N [--relay <id>]` builds the preimage receipt. `--relay` may be omitted when exactly one relay is configured. `weft price` prints `lightning` |
| Browser | The compose textarea becomes `pay`: voucher text or 64 hex characters of preimage. An `invoice` button asks the first relay that reports Lightning for the draft's cost, `(ceil((markdown + 512) / 1024) + 1) * days * rate`, and shows `bolt11` with the hash; the relay id rides along when the preimage is submitted |
| Theme | Tokens move to `light-dark()`; `:root` keeps `color-scheme: light dark`, `:root[data-theme]` pins one. On Linux `theme.rs` reads `org.freedesktop.appearance color-scheme` from the settings portal over `gio::DBusProxy`, stamps `data-theme` through an initialization script, and follows `SettingChanged`. No portal, no stamp. The no toggle decision survives; only the detection moves out of WebKit |
| Screenshots | `smoke.sh` stamps `data-theme` through the drive socket, shoots `docs/browser-home-light.png` and `docs/browser-home.png`, then writes `docs/browser-home.sha256`, the sha256 of `index.html`, `style.css`, `src/main.ts` in that order. `crates/browser/tests/drift.rs` recomputes it and fails with the script's name. The README shows both through `<picture>` |
| Login smoke | `smoke.sh` starts `weft-gateway` on a random loopback port against home b's daemon, GETs `/login`, follows to the challenge page, extracts the `weft:login?c=` link, submits it through the address bar, drives the consent dialog, then GETs `/login/<nonce>` and asserts the session cookie |
| Dependencies | `sha2 0.10` default features off in `weft-core` and as a dev dependency of `weft-browser`; `serde_json 1.0` with `std` and `reqwest`, `data-encoding` in `weft-relay`. All already in `Cargo.lock` |

## Plan

1. Core: `Payment`, `Receipt.payment`, `id`, one of two keys enforced in
   `decode` with negative tests for both, neither, and a short preimage.
   Vectors gain a preimage receipt and the rejections; regenerate.
2. Wire: `invoice` request and response, `lightning` on `price`, limits
   and negative tests for a zero and an oversized `cents`, an oversized
   `bolt11`, a short hash.
3. Net: `node.rs` with `Node`, `Invoice`, `Fake`; the index `invoices`
   table with issue, lookup, removal in `commit`, expiry in `sweep`;
   `Pricing.sats`; `Relay::open` takes `Option<Arc<dyn Node>>`; `invoice`
   answered from the node; `settle` by preimage. Tests: pay by preimage
   and pin, refuse an unknown hash, an expired invoice, an underpaid one,
   a reused preimage, a relay with `sats` 0, and the open invoice cap.
4. Client `invoice` and `Quote`; relay binary `sats`, `node`, `lnd.rs`,
   `price` output; CLI `invoice`, `push --preimage --relay`, `price`.
5. Browser: `invoice` command, `publish` with `pay` and `relay`, the UI
   field and button, `theme.rs` and the initialization script,
   `light-dark()` tokens.
6. Smoke: a Lightning publish through the fake node's preimage file, the
   gateway login flow, the two screenshots, the hash. `drift.rs`.
7. Close: docs, README Pay Flag, Login Flag, Briefing picture, loadout,
   handoff, backlog, verify, CI, land.

## Delivered

- Core: `Payment` of `Voucher` or `Preimage`, a receipt carries exactly
  one, its id is the voucher id or the hash address of `sha256(preimage)`.
  Vectors gained a preimage receipt and three rejections.
- Wire: `invoice` request and response, `sats` on `price`, limits and
  negative tests. Relay: `Node` trait, `Fake` node writing preimages to
  `data/preimages/<hex hash>`, an `invoices` table capped at 4096 and
  swept at expiry, settle by preimage against that table alone. Seven
  new relay tests cover paying, replay, unknown, underpaid, expired,
  sweep, and a relay without a node.
- Binaries: `weft-relay sats`, `node fake`, `node lnd <url>` with an LND
  REST adapter trusting only `lnd.pem`; `weft invoice`, `weft push
  --preimage --relay`, `price` and `receipts` show the rail.
- Browser: `invoice` command and button, the pay field takes voucher text
  or a preimage, `light-dark()` tokens with `data-theme` stamped from the
  settings portal at start and on change, `tests/drift.rs` against
  `docs/browser-home.sha256`.
- Smoke: a CLI publish paid over the fake node, a browser publish paid the
  same way, a gateway login through the consent dialog with the cookie
  claimed once and refused twice, both screenshots, and the hash.

## Deviations from the plan

- `price` carries `sats: uint` rather than `lightning: bool`: the CBOR
  subset in `protocol.md` has no boolean, and the number is what a payer
  needs anyway.
- `Relay::open` kept its signature; `with_node` attaches the node, so the
  six existing callers stayed untouched. `Index::issue` takes the cap as
  an argument so a unit test proves the refusal with a cap of two instead
  of issuing 4096 invoices.
- The smoke's first run failed at the very end: it fetched the login
  claim twice and the second fetch is a 403 by design. It now fetches once
  and asserts the 403.
