# M8

Status: complete, smoke tested on Linux with screenshots
Started: 2026-09-07

## Goal

Make the store the single gate. The browser becomes the daemon's one
privileged client: it never opens the keystore again, and every signature
it needs, for a page, a pointer, a revoke, or a login, is made by
`weft-store` over the socket. Applications keep the grant path unchanged.
Page rendering keeps reading records and blobs locally through
`weft-resolve`. The demo: start the daemon, publish and revoke from the
browser with no passphrase dialog, and watch the same requests refused
for an application key.

## Decisions

| Topic | Decision |
|---|---|
| Browser key | `<home>/browser.key`, 32 raw seed bytes, mode 0600, written with `create_new` by `weft-store serve` on first start. The daemon treats exactly that public key as privileged; every other key is an application under grants |
| Privilege | One check in `Gate`: the authenticated key equals the browser key. Privileged keys skip the grant lookup on `list`, `get`, `put`, and `login`. Reserved kinds stay refused on `put` for everyone; typed requests cover them |
| New requests | `kinds {}` counts verified own records per kind. `grants {}` returns the active grant records. `revoke { grant }` signs and stores a revoke. `publish { body, name? }` signs a `page` and, when `name` is given, the next pointer for it, stores both, and returns the records so the browser can push them. All four answer `refused: browser only` for an application key |
| New responses | `kinds { kinds: array of [text, uint] }`, `grants { records: array of bytes }`, `publish { records: array of bytes }`. `revoke` answers `put { address }` |
| Login | The browser sends `login` like an application, without a grant. The daemon signs, the browser posts the proof |
| Push | The browser pushes the returned records itself with the iroh client it already holds, prepending the local manifest record. The daemon never touches the network |
| Degradation | Daemon not running: navigation and rendering work, publish, revoke, login, and the store view answer `weft-store is not running`. No fallback to the keystore |
| Reads | Rendering stays on `weft-resolve` over the local record directory and blobs. Moving reads behind the socket is out of scope |
| Index | Not in scope. The gate snapshots the record directory per request |
| Dependencies | `weft-browser` depends on `weft-store`. Nothing new from crates.io |

## Layout

```
crates/store/src/gate.rs         browser key file, privileged check, kinds, grants, revoke, publish
crates/store/src/wire.rs         Kinds, Grants, Revoke, Publish requests and responses
crates/store/src/server.rs       answer the new requests
crates/store/src/client.rs       kinds, grants, revoke, publish
crates/store/src/bin/weft-store.rs  create the browser key at serve, print its address
crates/store/tests/gate.rs       browser privilege tests, negatives for applications
crates/browser/src/main.rs       store client instead of keystore, no passphrase commands
crates/browser/ui/index.html     device and passphrase fields removed
crates/browser/ui/src/main.ts    commands without device and passphrase
docs/store.md                    browser key, privileged requests, rules
```

## Plan

1. Store: browser key file helpers, `Gate::new` takes the browser key, privileged check in `allow`, `kinds`, `grants`, `revoke`, `publish` on the gate.
2. Wire: encode and decode the four requests and three responses with limits, malformed frame negatives.
3. Server and client: route the new requests, client methods.
4. Daemon: create the browser key with `create_new` on first serve, print it.
5. Tests: browser lists reserved kinds refused, application refused on every privileged request, browser login without a grant, publish yields a page and a pointer with the right `seq` and `prev`, revoke ends a grant on the next request, key file created once and mode 0600.
6. Browser: `store_client` helper mapping a missing socket to one message, `store_view`, `revoke_grant`, `publish`, `login` over the socket, passphrase and device inputs removed from the chrome, `identity` unchanged.
7. Docs: `store.md` gains the browser key and the privileged requests.
8. Smoke test the real binaries: daemon, browser publish and revoke without a passphrase, `weft-app` refused on `kinds`, browser with the daemon down. Screenshot the store view.

## Delivered

- Store: `<home>/browser.key` written by `weft-store serve` with
  `create_new`, mode 0600, reused on every later start and printed as
  `browser`. `Gate::new` takes the browser public key. One `allow` skips
  the grant lookup for that key; reserved kinds stay refused for everyone.
- Wire: `kinds`, `grants`, `revoke`, `publish` requests, `kinds`, `grants`,
  `publish` responses, name and array limits, round trip and malformed
  frame tests. Every privileged request answers `refused: browser only`
  for an application key.
- Gate: `kinds` counts verified own records, `grants` returns active grant
  records, `revoke` refuses a grant that is not active and otherwise signs
  and stores a revoke, `publish` signs a page and the next pointer for a
  name, verifies both, stores both, and returns them. Signing happens
  before any write so a refused pointer leaves no page behind.
- Browser: no keystore, no passphrase, no device fields. Store view,
  revoke, publish, and login go over the socket with the browser key; the
  browser pushes the returned records itself. A missing key file or a
  refused connection reads `weft-store is not running`. Rendering still
  reads the home directory through `weft-resolve`.
- Docs: `store.md` gains the browser key, the requests, and the rules.
- 71 tests in the workspace, 5 new.
- Smoke test with release binaries in a scratch home: init, device,
  manifest, daemon prints the browser address and the key file is 0600
  and 32 bytes, a restart reuses it, app key, grant, `weft-app write` and
  `read`. Browser store view over the daemon, revoke with no passphrase,
  `weft-app read` refused and `weft grant list` empty. Compose with a
  pointer name, page signed by the laptop key and served from the local
  store at `root/home`. Gateway on 8090, login dialog with no passphrase,
  logged in as the root, gateway page answers 200. Daemon stopped: the
  page still renders, the store view says `weft-store is not running`.
  Screenshots of the store view before and after the revoke, the compose
  result, the resolved page, the login dialog and result, and the daemon
  down message.

## Deviations from the plan

- The socket path must fit `SUN_LEN`; the smoke home moved to `/tmp`.
  Not a code change, but a long `WEFT_HOME` is a real failure mode.
- The application side of `kinds`, `grants`, `revoke`, and `publish`
  being refused is covered by the gate tests only; `weft-app` has no
  command that sends them.
- The wire test was split into request and response halves to stay under
  the clippy line limit.

## Open for M9

- Rendering reads still come from the home directory. Moving them behind
  the socket needs a store trait in `weft-resolve` and blob streaming.
- With no daemon the browser is read only. Spawning `weft-store serve`
  from a passphrase prompt is a later choice.
- `browser.key` is written once; rotation is delete and restart.
- The gate snapshots the record directory per request. Index still open.

## Out of scope

- Reads for rendering over the socket.
- Store index.
- Spawning the daemon from the browser.
- Application display names.
- Login through the daemon from the CLI; `weft login sign` keeps the keystore.
