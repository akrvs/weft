# M22

Status: complete, recovery driven end to end on the CLI, LND settled in regtest
Started: 2026-09-15

## Goal

Answer the two open questions the roadmap left standing and close the two
backlog rows this machine can reach. A root key gets social recovery: the
manifest names guardians and a threshold, and a record signed by enough of
them hands the identity to a new root that every resolver follows. Record
kinds are declared what the code already made them, an open namespace
with a reserved core. The LND adapter is run against a real regtest node
in containers and fixed where it is wrong. The browser theme falls back to
GSettings and GTK when the settings portal is absent.

## Decisions

| Topic | Decision |
|---|---|
| Guardians | The manifest body gains `guardians`, an array of bytes(32) sorted, unique, at most 16, none the root, and `threshold`, a uint from 1 to the guardian count. Both present or both absent. A guardian is another identity's root key. Existing manifests without the keys stay valid and their vectors do not move |
| Recovery record | `kind = "recovery"`, reserved, never grantable, stored and relayed. `author` is the lost root, `signer` is the new root. Body: `to` bytes(32) equal to `signer` and not `author`, `seq` uint, `prev` array of at most 16 recovery addresses also listed in `refs`, `sigs` array of 1 to 16 maps `{ key: bytes(32), sig: bytes(64) }` sorted by key, unique. Each guardian signs `weft/recovery/1 || 0x00 || canonical({ author, prev, seq, to })` |
| Verification | One branch in `verify`: a recovery needs the author's manifest, every `sigs` key must be a guardian and verify strictly, and the count must reach `threshold`; the device authorization step is skipped for this kind alone. Too few valid guardian signatures is `Error::Threshold`. The old root cannot sign a recovery; a compromised root is out of scope, recovery is for a lost one |
| Head | Among valid recoveries for an author the head is the highest `seq`, then `created`, then the lowest address, the pointer rule. Guardians supersede a recovery by publishing a higher `seq` citing the earlier head |
| Redirect | `Resolver::redirect(author)` follows recovery heads at most 4 hops; a fifth hop or a cycle is `Error::Hops`. `head` and `title` redirect first, so `author/name`, `domain/name`, the gateway, and the browser all follow. A raw address never redirects |
| Discovery | The relay indexes the recovery head per author in a `recoveries` table and answers a new `recovery { author }` request with `recovery { record }`, absent when unknown. The store socket gains `recovery { author }`, browser only, answering `get` or `missing`. `Reads::recovery` sits next to `Reads::manifest` |
| CLI | `weft manifest [--guardian <address>]... [--threshold <n>]` sets guardians, omitted keeps the previous manifest's. `weft recover draft <old root> [--seq n]` prints the base64url guardian message, `weft recover sign <message>` signs it with the caller's root and prints hex key and signature, `weft recover finish <message> --sig <hex>...` signs the record as the new root, stores it, prints its address for `weft push` |
| Kinds | No code. `protocol.md` section 9 states the namespace is open: any valid kind text is allowed and carries no protocol rules unless listed there. `design.md` drops the question |
| LND | `crates/relay/lnd.sh` starts bitcoind and two lnd nodes in regtest through `podman` or `docker`, funds the payer, opens a channel, and writes the relay's `lnd.macaroon` (the invoice macaroon), `lnd.pem`, and the payer's url, macaroon, and pem into a directory. `crates/relay/tests/lnd.rs` is `#[ignore]`, reads `WEFT_LND=<dir>`, issues an invoice through `Lnd`, pays it over the payer's REST, and pushes a preimage receipt to a real `Relay`. `lnd.rs` moves under a small `lib.rs` so the test can reach it. CI does not run it |
| Theme | `theme.rs` picks one source at start: the portal, else GSettings `org.gnome.desktop.interface color-scheme` when the schema is installed, else GTK `gtk-application-prefer-dark-theme`. Each source is watched the same way it is read. `prefer-dark` is dark, `prefer-light` is light, `default` falls through to GTK. No source stamps nothing |
| Dependencies | None new. `gio` and `gtk` are already linked on Linux; `sha2`, `reqwest`, `serde_json` already in the relay's tree |

## Plan

1. Core: `guardians` and `threshold` on `Manifest` with negative tests for
   an unsorted list, a root guardian, a zero or oversized threshold, and
   one key without the other. `recovery.rs` with encode, decode, message,
   `compare`, `head`. The `verify` branch. Vectors in `recovery.json`:
   valid at threshold, below threshold, an unknown guardian, a duplicate
   guardian, `to` not the signer, signed by the old root, a manifest
   without guardians, a tampered signature. Regenerate and test.
2. Home and store: `Snapshot::recovery_record`, `Reads::recovery`, the
   store wire request, gate, server, client, `Local`. Negative test: the
   request is browser only.
3. Relay: `recoveries` table, head rule on put, sweep drops the entry
   with the record, `recovery` request, client call. Tests: head answered,
   superseded by a higher `seq`, a recovery below threshold rejected on
   put.
4. Resolver: `redirect`, `head` and `title` through it, `Error::Hops`.
   Tests: a recovery pulled from a relay redirects `author/home`; a chain
   of five errors; a raw address does not redirect.
5. CLI: manifest guardians, `recover` commands, the e2e test with three
   homes: root, guardian, new root; the old `author/home` resolves to the
   new root's page.
6. LND: `lib.rs`, `lnd.sh`, `tests/lnd.rs`. Run it here against the
   pulled images, fix the adapter, record the result.
7. Theme: the three sources in `theme.rs`, a unit test for the GSettings
   mapping.
8. Close: docs, README Recovery Flag and the LND transcript under the Pay
   Flag, handoff, backlog, verify, CI, land.

  `weft/recovery/1`, `Error::Threshold`, the verify branch that needs the
  author's manifest and skips device authorization for this kind alone,
  `recovery` in the reserved list. `vectors/recovery.json` holds a guarded
  manifest, sixteen records, and six bad manifests; four new protocol
  tests cover the threshold, the signer, the head rule, and guardian
  lists.
- Home and store: `Snapshot::recovery_record` picks the head among valid
  recoveries, `Reads::recovery`, the `recovery` request over the store
  socket, browser only, through gate, server, client, and `Local`.
- Relay: a `recoveries` table keyed by author, replaced on put by the head
  rule and dropped with its record, `recovery` request and response,
  `Client::recovery`. A test serves the head, refuses a stranger's

- Resolver: `recovery` collects local and relay candidates, verifies each

  so `title`, the gateway, and the browser follow. Two tests: a recovery
  pulled from a relay redirects `author/home` and survives offline, and a
  chain of five hops fails while four pass.
- CLI: `weft manifest --guardian --threshold`, `weft recover draft`,
  `sign`, `finish`, `resolve` printing `recovered to` when it followed a

## Deviations from the plan

- The adapter was wrong in one place the fake node could not show: LND's
  autogenerated certificate is `CA:TRUE`, and webpki refuses a CA as a
  leaf, so `tls_certs_only` could never connect. The fix pins the exact
  certificate through a custom `ServerCertVerifier` instead of trusting it
  as a root, which is stricter and matches what an operator copying
  `tls.cert` means anyway.
- `gio::Settings` and `gtk::Settings` are not `Send`, so the theme source
  lives in a `thread_local` on the main thread instead of Tauri state,
  and `watch` returns nothing.
- `Message` gained a type with `encode` and `decode` so the CLI can show a
  guardian what they are signing and refuse a malformed draft.
- The relay's head request stayed as it was; recovery got its own
  `recovery` request rather than a third field on `head`.
