# M20

Status: complete, smoke driven end to end on Linux with the release binaries
Started: 2026-09-15

## Goal

Take the four browser rows of `BACKLOG.md` that this machine can close.
Named links render: a page may link `weft:author/name` or
`weft:domain/name` and the browser resolves it on click, as the address
bar would. A blob pull shows its total before the first byte through a
`size` request on the relay wire. The smoke test drives the browser's
dialogs through a feature gated socket instead of a human hand, and
screenshots the light and the dark theme into `docs/`.

## Decisions

| Topic | Decision |
|---|---|
| Named links | `render` accepts any `weft:` link whose rest parses as a `Target` and emits `<links.record><target>` where the target's text form is the address, `author/name`, `host` for `home`, or `host/name`. Nothing is resolved at render time; the browser's click handler and the gateway's path router already take that grammar. Images stay blob addresses only. Reopens the M3 freeze at the user's request |
| Blob total | New relay request `size { address: bytes(32) }` answered by `size { bytes: uint }`, `bytes` absent when the relay holds no complete blob at that hash. `Client::pull_blob` asks once before the download; a relay that refuses the request, one older than this version, leaves the total unknown and the pull proceeds. Progress callbacks become `FnMut(u64, Option<u64>)`, the resolver `Watch` becomes `Fn(Address, u64, Option<u64>)`, the `pull` event carries `total`, and the bar is determinate when the total is known |
| Drive socket | Cargo feature `drive` on `weft-browser`, off by default, absent from the release build and from CI. With it, `WEFT_DRIVE=<path>` binds a Unix socket, mode 0600, in `setup`. One connection is one JavaScript expression read to EOF, at most 1 MiB, evaluated in the `chrome` webview as `await (<expr>)`; the reply is the JSON of `{ok: value}` or `{err: text}`, then the connection closes. The result travels through a `window.__drive<n>` slot polled with `eval_with_callback` every 20 ms for up to 60 s, so no command joins the invoke surface. Without the variable the feature does nothing |
| Smoke script | `crates/browser/smoke.sh` builds with `--features drive`, starts a relay, a bank, and the browser against a scratch home under `$XDG_RUNTIME_DIR`, then drives compose, pay, store names and repoint, history, and bookmarks through the socket, asserting on the DOM after each step. It screenshots with `grim -g` on the window's geometry from `hyprctl clients` |
| Theme | Untouched: tokens follow `prefers-color-scheme`. The light shot was dropped: WebKitGTK 2.52 on this Hyprland box renders the content `prefers-color-scheme: dark` whatever the portal reports, so no light page can be captured here. See Deviations |
| Screenshots | `docs/browser-home.png`, the home page with the provenance line open, linked from the README briefing. Refreshed by the script, never by hand. The script no longer touches `gsettings` |
| Dependencies | None added. `serde_json` is not needed: the JavaScript side stringifies |

## Plan

1. Wire: `size` in `docs/relay.md`, `Request::Size`, `Response::Size`, encode
   and decode with negative tests for extra fields and a short address.
2. Relay answers `size` from `BlobStatus`; a relay test asks for a held
   blob, an unknown hash, and a blob after the sweep.
3. Client `size` and `pull_blob` with a total; the CLI and the tests
   adapt their callbacks; the resolver's `Watch` carries the total and
   the pull test asserts it.
4. `Target` gets `Display` with a round trip test; `render` emits named
   and domain links with tests for each form, for `home`, and for the
   rejections that stay: a hash author with a name, two slashes, a
   control character, an uppercase domain label, `weft:login?`.
5. Gateway: a test that a rendered named link resolves through
   `route` at `/author/name`.
6. Browser: `Pull.total`, the bar's width bound to it, `drive.rs` behind
   the feature, `WEFT_DRIVE` in `setup`.
7. `smoke.sh`: build, start, drive, assert, screenshot the home page into
   `docs/`, stop everything. Run it.
8. Close: README screenshot and flag text, handoff, backlog, verify, CI,
   land.

## Delivered

- Relay wire `size { address }` -> `size { bytes }`, `bytes` absent for a
  blob the relay lacks. `Client::size` and `pull_blob` with a
  `(done, total)` callback; the resolver `Watch` and the `pull` event
  carry the total; the bar is determinate when it is known.
- `render` emits any `weft:` link whose rest parses as a `Target`, in the
  target's text form, resolved on click by the browser or the gateway
  path router. `Target` gained `Display`. Images stay blob addresses.
- `drive` feature on `weft-browser`, off by default: `WEFT_DRIVE=<socket>`
  evaluates one JavaScript expression per connection in the chrome
  webview, `{"ok":..}` or `{"err":..}` back. `crates/browser/smoke.sh`
  drives start, navigation, a named link, a pull with its total, the blob
  save panel, bookmark, history, compose with a paid publish, and store
  repoint, asserting on the DOM after each and screenshotting the home
  page.

## Deviations from the plan

- The light theme screenshot was dropped. WebKitGTK 2.52 on this Hyprland
  machine renders the page `prefers-color-scheme: dark` no matter what the
  portal reports; the palette in the stylesheet is correct (`--bg`
  `#f7f6f2` on bare `:root`) but the content never repaints light. Tested
  the portal `color-scheme` at `default`, `prefer-light`, and a light
  `gtk-theme`: the titlebar turned light, the web view stayed dark. Making
  it light needs a `WebKitSettings` call or a `data-theme` override, both
  of which reopen the frozen "follows the system, no toggle" decision, so
  the item stays in `BACKLOG.md`. The README shows one dark screenshot and
  `smoke.sh` no longer mutates `gsettings`.
- The drive result travels through a `window.__drive<n>` slot polled by
  `eval_with_callback`, not a single awaited eval: `eval_with_callback`
  resolves before a returned promise settles, so the socket handler starts
  the async expression, then polls the slot until it is set.
