# M17

Status: complete, smoke tested on Linux with the release binaries
Started: 2026-09-14

## Goal

Operational loose ends from the backlog. Network commands run without
internet, the store cache has a byte cap, the browser can start a daemon
that outlives it, the gateway's session and identity caps are flags with
eviction instead of refusal, and the CLI exits quietly on a closed pipe.
No protocol or wire change. The demo: `WEFT_NET=local` on one machine
pushes to and resolves from a relay with the network cable out; a store
of more records than the cap answers every read; the browser closes and
`weft-store` keeps serving; a gateway at `--sessions 2` logs a third
identity in by dropping the oldest; `weft relay list | head -1` exits 0.

## Decisions

| Topic | Decision |
|---|---|
| Local network | One `weft_net::Net` read from `WEFT_NET`: unset is the public iroh network, `local` binds `presets::Minimal` with iroh relays disabled and mDNS address lookup through `iroh-mdns-address-lookup`, any other value is an error. `Client::bind` and `weft-relay serve` build through it. `Net::online` waits for a relay only in public mode, since iroh's `online` never returns with relays disabled. Relay ids stay bare in the relay list |
| Cache cap | `Store` cache counts encoded record bytes and evicts least recently used records past the cap, default 256 MiB, `weft-store serve --cache <MiB>`, 0 unlimited. The verified memo follows the record out. Reads past the cap fall through to disk. The snapshot still walks the directory, so a store larger than the cap re-reads evicted files on every request; that is the cost of the bound |
| Detach | `weft-store serve` without `--attach` reads the passphrase as one line from standard input when standard input is not a terminal, prompts otherwise. The browser's start form gets a `keep running after the browser closes` checkbox; checked, it spawns without `--attach` in its own process group and closes the pipe after the passphrase. The daemon logs nothing after start, so the closed standard error pipe is harmless |
| Gateway caps | `--sessions` and `--identities`, default 4096 each, environment `WEFT_GATEWAY_SESSIONS` and `WEFT_GATEWAY_IDENTITIES`. A full sessions table evicts the login that expires soonest; the budget table keeps evicting the oldest window. Loading a file with more entries than the cap keeps the newest and drops the rest, so lowering a flag never refuses to start. Pending challenges keep a fixed cap of 1024 in memory and still refuse, since they are anonymous. `Gateway::new` takes one `Limits` value in place of the two builders |
| Closed pipe | The CLI prints through one `say!` macro that exits 0 when standard output reports a broken pipe. Only `weft` changes; the daemons print a few lines at start and are not piped |
| Dependencies | `iroh-mdns-address-lookup` 0.5 in `weft-net`, MIT or Apache-2.0, pulls `swarm-discovery` |

## Plan

1. Net: `Net::from_env`, `builder`, `online`; unit tests for the three
   env shapes; a loopback test that a client in local mode reaches a relay
   by id alone through mDNS.
2. Cache: byte accounting, LRU eviction, cap through `Store::with_cache`
   and `Home::with_cache`, `--cache` on the daemon. Tests: reads past the
   cap still answer, the resident set stays under the cap, a hit refreshes
   order, a retained record keeps its size right.
3. Detach: passphrase from a pipe without `--attach`, checkbox and flag,
   process group. Test: the daemon started with a pipe and no `--attach`
   stays up after the pipe closes.
4. Gateway: `Limits`, eviction, load keeps newest, flags. Tests: the third
   login at `sessions 2` drops the soonest expiry; a file over the cap
   loads the newest; the budget table honours the flag.
5. CLI: `say!`, replace every `println!`, integration test with a reader
   that closes after the first line on output over the pipe buffer.
6. Docs, README, smoke test the release binaries, close.

## Delivered

- `weft_net::Net`: `WEFT_NET` unset is the public iroh network, `local`
  is `presets::Minimal` with iroh relays disabled and mDNS lookup under
  the service name `weft` through `iroh-mdns-address-lookup` 0.5, any
  other value is an error. `Client::bind` and `weft-relay serve` go
  through it; `Net::online` skips the relay wait in local mode. A test
  reaches a relay by id alone over loopback mDNS.
- Store cache: encoded bytes counted, least recently read record evicted
  past the cap, 256 MiB default, `weft-store serve --cache <MiB>`, 0
  unlimited, `Store::with_cache`, `Home::with_cache`, `cached_bytes`.
- Daemon: the passphrase comes from standard input whenever it is not a
  terminal, `--attach` alone adds the exit on EOF. The browser start form
  has `keep running after the browser closes`, which spawns without
  `--attach` in its own process group and closes the pipe. Two binary
  tests: a piped daemon without `--attach` outlives its pipe, one with
  `--attach` exits and removes its socket.
- Gateway: `Limits { pulls, budget, sessions, identities }` replaces the
  two builders; `--sessions` and `--identities` default 4096, refused
  above the CBOR array limit of 4096 with `Refusal::Cap`. A full sessions
  table drops the login that expires soonest; a full budget table drops
  the oldest window; a file over the cap loads its newest entries.
  Pending challenges keep a fixed cap of 1024 and still refuse.
- CLI: every `println!` is `say!`, which exits 0 on a broken pipe and 1
  with a message on any other write error. A test closes the pipe after
  the first of 1500 relay lines.
- Tests: 111 in the workspace, up from 103.
- Smoke test with release binaries: `WEFT_NET=local` relay, push of 4
  records from one home, resolve from another by relay id alone,
  `WEFT_NET=bogus` refused, `weft whoami | head -1` exit 0; a daemon
  started from a pipe with `--cache 1` alive after its stdin closed; a
  gateway at `--identities 4097` refused, at `--sessions 2` three logins
  succeeded, the file held two, the first cookie got 303 at `/login` and
  the other two 200. The browser start form renders the checkbox; the
  detached start was not clicked through in the GUI.

## Deviations from the plan

- The verified memo does not follow an evicted record out; it is pruned
  by the snapshot as before. Dropping it per eviction would scan the memo
  on every insert past the cap.
- The caps are bounded at 4096 by the CBOR array limit, which the plan
  did not know about; `cbor::MAX_ITEMS` is now public and the gateway
  refuses a larger flag rather than writing a file it cannot read back.
- `Limits` replaced the `budget` and `pull_cap` builders instead of
  adding two more.
