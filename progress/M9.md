# M9

Status: complete, smoke tested on Linux with screenshots
Started: 2026-09-07

## Goal

Finish the store as the single gate. The browser stops reading the
record directory and the blob directory: every record, manifest,
pointer, and blob it renders comes over the socket, and every record it
fetches from a relay goes back through the daemon. The gate stops
re-reading and re-verifying every record per request behind an
in-memory index that every writer to the directory still keeps honest.
With no daemon the browser offers to start one from a device label and a
passphrase, and the daemon lives exactly as long as the browser does.
The demo: start the browser cold, start the store from its dialog, open
a page whose blob crosses the socket in chunks, close the browser, and
watch the daemon go with it.

## Decisions

| Topic | Decision |
|---|---|
| Reads trait | `weft_home::Reads`: `record`, `manifest`, `pointers`, `blob`, `keep`, each returning a `Send` future. `Store` implements it over the directory; `weft_store::Local` implements it over the socket with the browser key. `Resolver<R: Reads>` defaults to `Store`; the CLI and gateway keep the directory through `Resolver::local`, the browser uses `Local` and never opens `records/` or `blobs/` |
| Verification | Unchanged choke point: the resolver verifies what it renders, the gate verifies what it stores. `Reads` returns candidates, never trust |
| New requests | `record { address }`, `manifest { author }`, `pointers { author, name }`, `blob { address, offset }`, `keep { record }`. All five browser only. `record` and `manifest` answer `get` or `missing`; `pointers` answers `records`; `keep` answers `ok` |
| Keep | The gate verifies the record against the newest local manifest for its author, or against nothing when it is a manifest, then stores it. Login records stay refused. Anything that does not verify is refused |
| Blobs | `blob { address, offset }` answers `blob { total, chunk }` with a chunk of at most 512 KiB read from the file at `offset`, or `missing`. The client loops until `total`, refuses a `total` above 1 GiB or one that changes between chunks, and the resolver verifies the blake3 hash of the whole. The frame limit stays 1 MiB |
| Index | `Store` holds an `Arc` cache shared by every clone from the same `Home`: parsed records by address, and verification outcomes keyed by record address and manifest hash. `snapshot()` lists the directory each time and parses only unseen files, so CLI writes stay visible. `record(address)` opens the one file. The static helpers become `Snapshot` methods; `Store::head` stays |
| Spawn | `weft-store serve --device <label> --attach` reads the passphrase as the first line of stdin and exits when stdin closes. The browser spawns the binary beside its own executable, or `weft-store` on the path, pipes the passphrase, waits for the socket, and holds the pipe until it exits. No kill, no signal dependency |
| Spawn dialog | The store dialog shows a start form when the daemon is not running: device select from the keystore labels, passphrase field. Errors from the child's stderr are shown as is |
| Blob view | The `weft://blob/` scheme becomes an asynchronous protocol handler over the socket; inline page images render to the same scheme |
| Degradation | Daemon not running: the browser renders nothing local and says so on every navigation; the start form is one click away. Relay fetches still work but are not kept |
| Dependencies | Nothing new from crates.io. `weft-browser` gains `tokio` and `zeroize` from the workspace |

## Plan

1. Home: `Store` with a shared cache and `snapshot()`, `Snapshot` methods replacing the statics, `record(address)` by file, `Reads` trait and its `Store` impl. Migrate the CLI, gate, daemon, and gateway tests.
2. Wire: five requests and three responses with limits and negatives.
3. Gate: `record`, `manifest`, `pointers`, `blob`, `keep`, browser only, with `keep` verifying before `put`. Server routes, client methods, `Local` with blob assembly.
4. Resolve: `Resolver<R>`, every local read and keep through the trait, `blob` async. Gateway follows.
5. Daemon: `--attach`.
6. Tests: applications refused on all five, keep refuses an unverifiable record and a login, blob crosses in chunks and a bad hash is refused, snapshot sees a record written by another `Store` on the same directory.
7. Browser: `Local` for the resolver, asynchronous blob protocol, `start_store` command holding the child, `devices` labels, start form in the store dialog.
8. Docs, smoke test with screenshots: cold browser, start from the dialog, image blob over the socket, browser exit takes the daemon.

## Delivered

- `weft_home::Store` takes the home directory, owns `records/` and
  `blobs/`, and shares a cache of parsed records and verification
  outcomes between every clone from one `Home`. `Snapshot` replaces the
  static helpers. `Reads` is the trait every local read goes through.
- `Resolver<R: Reads>` with `Resolver::local` for the directory. Blobs
  are hashed in the resolver after any `Reads`; a forged blob file is a
  404 at the gateway.
- Store wire: `record`, `manifest`, `pointers`, `blob`, `keep` requests;
  `records`, `blob`, `missing` responses; chunk, blob, and record limits
  with negatives.
- `Gate` answers the five for the browser key only, verifies before
  `keep`, serves blobs by offset from the file.
- `weft_store::Local` implements `Reads` over one connection to the
  daemon, reconnects once after the daemon's idle close, and reports a
  missing daemon as one error.
- `weft-store serve --attach`: passphrase from stdin, exit on stdin EOF.
- Browser: `Resolver<Local>`, asynchronous `weft://blob/` handler,
  `start_store` command holding the child, start form in the store
  dialog, inline images through the blob scheme.
- Tests: 76 passing, 5 new. Smoke test on Linux: cold browser reports
  the missing daemon, the dialog starts it with the laptop device, a
  1.4 MiB image blob renders in three chunks, a navigation after the
  60 second idle close succeeds, closing the browser ends the daemon and
  removes the socket.

## Deviations from the plan

- `Store::new` takes the home directory instead of the record
  directory so the filesystem `Reads` can find blobs. The CLI `--dir`
  flag now names a directory holding `records/` and `blobs/`.
- `Local` retries a call once when a reused connection fails, because
  the daemon closes idle connections after 60 seconds and the first
  smoke test hit a broken pipe.
- `Links::WEFT` renders images to `weft://blob/<address>`. WebKit never
  handed `weft:<address>` image requests to the scheme handler, so
  inline images had not rendered in the browser before.
- `Resolver<Store>` gained `local(home)` so the gateway and tests do not
  spell out the clone.

## Open for M10

- The browser reads the daemon's stderr only when the start fails; a
  daemon that writes more than the pipe buffer afterwards would block.
- The record cache never evicts and the verification memo grows with
  every manifest that ever applied.
- `Local` holds one connection, so browser requests to the daemon are
  serialized.
- A navigation with the daemon down reports it but does not open the
  start form; the store dialog does.
- The gateway still reads the directory. A gateway behind a daemon is a
  separate deployment question.

## Out of scope

- Store index on disk.
- Blob pull on miss and blob writes over the socket.
- Detached daemon or restart on exit.
- Application display names.
- Browser key rotation.
