# M4

Status: in progress
Started: 2026-09-06

## Goal

The first registry and the first bridge. A `_weft` TXT record binds a
domain to a root key, looked up over DNS over HTTPS with the resolver's
DNSSEC verdict carried as provenance. The browser address bar accepts
`example.com` and `example.com/blog`. A gateway binary serves every form
the address bar accepts to browsers that do not speak Weft, with the same
provenance in a header bar and in response headers. The demo from the
roadmap: the same page in Firefox through the gateway and in Weft through
the domain.

## Decisions

| Topic | Decision |
|---|---|
| DNS transport | DNS over HTTPS through hickory-resolver 0.26, already in the lock via iroh, features `https-ring` and `webpki-roots`. Resolver pinned to Cloudflare, overridable by `WEFT_DOH` as `ip,server name` |
| DNSSEC | Not required. The AD bit of the answer is recorded and shown as `dnssec: yes` or `no`. Full validation is a later option |
| TXT format | `_weft.<domain>` TXT `weft=<key address>`. Exactly one `weft=` record, a key address, or the domain does not resolve |
| Bare domain | `example.com` opens `example.com/home`; `example.com/<name>` opens that pointer |
| Domain syntax | Lowercase ASCII labels of letters, digits, and inner hyphens, 1 to 63 bytes each, at least one dot, at most 253 bytes. Anything else is not a domain |
| Shared resolver | New crate `weft-resolve` holds target parsing, DNS, record and pointer resolution, and the Markdown renderer moved out of the browser. Browser and gateway are thin over it |
| Gateway server | New binary `weft-gateway` on hyper 1 with `http1` only, `hyper-util` for the Tokio adapter. Plain HTTP on an explicit bind, default `127.0.0.1:8080`. TLS is the reverse proxy's job |
| Gateway paths | `/<address>`, `/<author>/<name>`, `/<domain>`, `/<domain>/<name>`, `/blob/<address>`, `/style.css`. Root is a form. GET and HEAD only |
| Gateway provenance | Header bar above the content and `x-weft-address`, `x-weft-author`, `x-weft-signer`, `x-weft-source`, `x-weft-name` response headers |
| Gateway CSP | `default-src 'none'; img-src 'self'; style-src 'self'; form-action 'self'` and `referrer-policy: no-referrer` |
| Link rewriting | The renderer takes a link map. Browser keeps `weft:` for both. Gateway maps record links to `/<address>` and images to `/blob/<address>` |
| CLI | `weft dns <domain>` prints the bound key and the DNSSEC verdict so a publisher can check the record |

## Layout

```
crates/resolve/    weft-resolve
  src/lib.rs       exports
  src/error.rs     typed Error
  src/target.rs    Target: Address · Named · Domain, one FromStr
  src/dns.rs       TXT parsing choke point · DoH lookup · Binding
  src/render.rs    Markdown to HTML with a Links map, moved from browser
  src/resolver.rs  Resolver over home, store, client, dns · Page
crates/gateway/    weft-gateway
  src/main.rs      args · listener · routes
  src/html.rs      header bar · form · error pages · stylesheet
  tests/serve.rs   end to end over loopback
```

## Plan

1. `weft-resolve`: `Target` with negative tests for every rejection,
   `dns::parse` over fixture TXT answers with negative tests, `render`
   moved with the link map and its eight tests, `Resolver` moved from the
   browser with `Page` gaining `name`.
2. Browser depends on `weft-resolve`, drops its own copies. Provenance
   panel shows the name tier. No other UI change.
3. `weft-gateway`: hyper http1 server, request limits, routes, HTML with
   the header bar, headers, CSP. Integration test over an ephemeral port
   with a signed page in a temporary home: address, author name, blob,
   404, 400, 405, path traversal.
4. `weft dns <domain>` in the CLI.
5. CI builds the new crates with the workspace. `deny.toml` unchanged
   unless the audit says otherwise.
6. Smoke test: gateway serving a real signed page to Firefox, browser
   opening the same page by `author/name`. Domain resolution verified by
   tests only; no domain is available for a live record.

## Out of scope

Petnames, DNSSEC validation in the client, gateway TLS, host based
gateway routing, gateway caching and rate limits, gateway compose,
browser history, mobile.
