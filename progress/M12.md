# M12

Status: complete, smoke tested on Linux with the real binaries
Started: 2026-09-08

## Goal

Reads that fetch. When the local store lacks a blob, the browser and the
gateway pull it from the home relay list the way they already pull
records, hand it to the daemon over the socket, and serve it once the
daemon holds it. The DNS bridge remembers a binding for its TTL instead
of asking Cloudflare on every navigation. The demo: publish a page with
an image on the laptop, open it by name on a desktop whose store has
never seen the blob, the image renders and the daemon now has it; open
it again with the relay stopped, it still renders.

## Decisions

| Topic | Decision |
|---|---|
| Who pulls | The client. `Resolver::blob` on a local miss asks each relay in turn over iroh-blobs, hashes the whole against the address, and stores it through `Reads::keep_blob`. The daemon stays off the network |
| Socket | New request `keep-blob` with `address`, `total`, `offset`, `chunk`, answered `ok`. Browser only. Chunks at most 524288 bytes, total at most 1 GiB. The daemon appends to `<home>/blobs/<address>.part`; offset 0 starts the file fresh, any other offset must equal the part length; when the part reaches `total` the daemon hashes it and adopts or discards it. A blob already present answers `ok` without writing |
| Choke point | `Store::keep_blob` refuses data whose blake3 does not match the address. Every path into `blobs/` goes through it |
| Gateway | Pulls like records, no flag. A blob found nowhere answers 404 `blob not found` |
| Timeouts | Relay requests keep the 5 s timeout; a blob pull gets 120 s per relay |
| DNS cache | Per `Dns`, keyed by host, expires at the lowest TTL of the TXT answers clamped to 60 s minimum and 3600 s maximum, at most 1024 entries, the earliest expiry evicted when full. Failures are not cached |
| Tests | Resolver tests run a loopback relay with `presets::Minimal` and a client whose endpoint carries the relay's address through `MemoryLookup`; `Resolver::with_client` injects it |
| Dependencies | `iroh` as a dev dependency of `weft-resolve`. Nothing new in the workspace |

## Plan

1. `Store::keep_blob` checks the hash, `Reads::keep_blob`, `Client::pull_blob`. Tests: wrong bytes refused, nothing written.
2. Socket `keep-blob`: wire, gate, server, client, `Local`. Tests: chunked round trip larger than one chunk, wrong hash refused and part removed, offset mismatch refused, offset 0 restarts a stale part, total changes refused, application key refused, empty blob, `Local::keep_blob`.
3. `Resolver::blob` pulls on miss and keeps; `with_client`. Test over a loopback relay: miss pulls and stores, second read is local, unknown address is `None`, relay stopped after the pull still serves.
4. DNS cache. Tests: hit within TTL, miss after, clamp both ways, eviction at 1024.
5. Gateway text and test. Docs, README, smoke test with the real binaries, close.

## Delivered

- `Store::keep_blob` refuses bytes that do not hash to their address; it
  is the only writer of `blobs/`. `Reads::keep_blob` on `Store` and
  `Local`. `weft_net::Client::pull_blob` downloads into memory.
- Socket request `keep-blob`: chunked upload into `<home>/blobs/<address>.part`,
  offset rules, hash on completion, part removed on refusal, browser only.
  `Client::keep_blob` streams; `Local` retries a stale connection from
  offset 0.
- `Resolver::blob` pulls from each relay in turn with a 120 s budget on a
  local miss, hashes, keeps, returns. `Resolver::with_client` injects a
  client so tests run over a loopback relay with `MemoryLookup`.
- `Dns` remembers a binding for its lowest TXT TTL clamped to 60 s to
  3600 s, at most 1024 hosts, the soonest expiry evicted when full.
- Gateway answers 404 `blob not found`. Tests: store rules, resolver pull
  over a real relay, DNS cache, gateway. 87 tests.

## Deviations from the plan

- No "total changes" rule on `keep-blob`: the part file does not record
  `total`, and the hash on completion catches every inconsistency.
- The gateway got no relay driven test of its own; the resolver test
  drives the same code over `Store`, the store tests drive `Local`, and
  the smoke test drove gateway, `Local`, daemon, and relay together.

## Open for M13

- Stale `.part` files after a crashed pull are never swept.
- The gateway pulls for anonymous readers with no rate limit, so a public
  gateway is a fetch proxy for its relay list.
- Browser blob pull is verified only through the shared resolver path,
  not by running the desktop app.

## Out of scope

- Progress display while a blob downloads.
- Negative DNS caching.
- Blob pull in the CLI beyond the existing `fetch --out`.
- Store cache cap.
