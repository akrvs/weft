# M11

Status: planned
Started: 2026-09-08

## Goal

Put the gateway behind the gate. It stops opening `records/` and
`blobs/` and reads everything through the store socket as the browser
does, so the daemon is the only process that touches signed state and
stopping it stops every reader. Gateway sessions survive a restart, and
an operator can name who may log in. The demo: start the daemon, open a
page through the gateway, log in, restart the gateway, still logged in;
stop the daemon, the same page answers 503.

## Decisions

| Topic | Decision |
|---|---|
| Store access | The gateway connects through `weft_store::Local` with `<home>/browser.key`. The privileged clients are the browser and the gateway; one key file, meaning a process on this host with home access. `Gateway` holds `Resolver<Local>`, no generic, no directory path |
| Store down | Record and blob requests answer 503 with the plain error page when the daemon is not running. No fallback to the directory. Login proofs still verify because they are self contained; the freshest manifest lookup is best effort as before |
| Sessions | The session map is written to `<home>/gateway/sessions` as canonical CBOR through `replace_private` on every insert and removal, loaded at start with expired entries dropped. A malformed file refuses start. Pending challenges stay in memory |
| Login policy | `--allow <path>` or `WEFT_GATEWAY_ALLOW`, one address per line, the relay's `allow` format. Given, only listed authors log in and others get 403. Absent, any valid identity logs in. A malformed line refuses start |
| Dependencies | `weft-store` added to the gateway. Nothing external |

## Layout

```
crates/gateway/Cargo.toml          weft-store
crates/gateway/src/lib.rs          Resolver<Local>, 503 on a missing daemon, allow check
crates/gateway/src/login.rs        sessions file, allowlist, Refusal::Denied
crates/gateway/src/main.rs         Local reads, --allow
crates/gateway/tests/serve.rs      daemon in the test world, down, restart, allow, malformed files
docs/store.md                      privileged clients
README.md                          gateway flags, persistence
```

## Plan

1. Gateway over `Local`: `Gateway::new(Resolver<Local>, origin, ...)`, main builds it, tests start a daemon. Test: pages and blobs serve through the socket, a stopped daemon answers 503.
2. Sessions file: load, save, prune. Test: a new `Gateway` on the same home honours the cookie, logout removes it from the file, a truncated file refuses start.
3. Allowlist: parse at start, check in `satisfy`. Test: a listed author logs in, an unlisted one gets 403, a bad line refuses start.
4. Docs, README, smoke test with the real binaries, close.

## Out of scope

- Gateway host based routing and TLS.
- `weft:` URL handler registration.
- Grants over fetched records.
