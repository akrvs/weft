# M3

Status: complete, smoke tested on Linux with screenshots
Started: 2026-09-03

## Goal

The browser, first cut. One window: an address bar that accepts a raw
address or `author/name`, a native renderer for `page` records written in
Markdown, a provenance panel on every record, an embedded web view for
HTTPS pages carrying the unsigned label, and a compose view that signs a
page with a device key and pushes it. The minimum end to end slice from
the design document.

## Decisions

| Topic | Decision |
|---|---|
| Shell | Tauri 2 with the `unstable` feature for multiple web views in one window |
| UI | Vanilla TypeScript compiled by `tsc`, no framework, no bundler, strict CSP |
| Page format | CommonMark without raw HTML, rendered in Rust by pulldown-cmark, HTML events dropped |
| Images | Only `weft:` blob addresses, served by a custom URI scheme from the local store |
| Links | `weft:` addresses open in the renderer; `https:` opens the child web view |
| Old web | Second web view in the same window below the chrome, labelled unsigned |
| Scope | Read, provenance, publish text. Shares the CLI home, keystore, and relay list |
| Shared code | `weft-home` crate extracted from the CLI: home, keystore, store, fs |

## Layout

```
crates/home/       weft-home: home · keystore · store · fs
crates/browser/    weft-browser: Tauri app
  src/main.rs      commands: resolve · fetch · render · identity · publish · open_web
  src/render.rs    Markdown to sanitized HTML
  tauri.conf.json  identifier, frontendDist, CSP
  capabilities/    core:default for the chrome web view only
  ui/              index.html · style.css · src/*.ts · tsconfig.json
```

## Plan

1. Extract `weft-home` from the CLI. No behaviour change.
2. `render` module: pulldown-cmark with tables and strikethrough, drop
   `Html` and `InlineHtml` events, allow only `weft:` image sources and
   `weft:` or `https:` link targets, escape everything. Fixture tests
   including injection attempts.
3. Tauri app. State holds the home, a client bound lazily, and the
   record store. Commands return typed results serialised as JSON.
   Custom scheme `weft` serves blob bytes by address from the local
   blob directory after verifying the hash.
4. Chrome UI in TypeScript: address bar, resolve and render flow,
   provenance panel, compose form with passphrase prompt, unsigned
   banner when the web view is showing.
5. Child web view: created on demand for `https:` URLs, positioned
   under the chrome, resized with the window, `on_navigation` restricted
   to `https:`.
6. CI: install webkit2gtk and node on the runner, `tsc --noEmit` and
   `cargo build` for the browser crate. Tests stay headless.

## Out of scope

DNS names, petnames, personal store views, grants, login, payments,
tabs, history, bookmarks, mobile.

## Delivered

- `weft-home` extracted from the CLI with no behaviour change.
- `weft-browser`: Tauri 2 app with commands `resolve`, `initial`,
  `identity`, `publish`, `open_web`, `close_web`; custom `weft` scheme
  serving blobs by address after re-hashing; Markdown renderer over
  pulldown-cmark events with a fixed element set, raw HTML dropped, links
  limited to `weft:` and `https:`, images to `weft:` blob addresses.
- Chrome UI in TypeScript compiled by `tsc` with strict settings, no
  framework, no bundler, no inline script, CSP with no remote origins.
- Child web view for HTTPS pages, incognito, navigation restricted to
  `https:`, below a fixed chrome with the unsigned banner.
- Eight renderer tests covering script injection, attribute injection,
  javascript and http links, remote and data images, code block class
  injection, tables, and oversized input. 27 tests in the workspace.
- Smoke test on Linux: `author/name` resolves from the local store,
  renders the Markdown page with provenance, drops a script tag in the
  body; `https://` opens the page under the banner at the right size.
- CI installs webkit2gtk and node, type checks and builds the UI, then
  builds the browser with the rest of the workspace.

## Deviations from the plan

- Tauri positions child web views only on Windows and macOS. On Linux
  they are packed into a vertical GtkBox with equal expansion. The
  browser reaches into GTK through the `gtk` crate Tauri already
  depends on: the chrome is wrapped in a ScrolledWindow with external
  scroll policy so its natural height does not propagate, and packing is
  toggled between a fixed 88 px and full expansion when the web view
  opens and closes.
- Relay lookups are local first with a 5 second timeout per relay so an
  offline relay does not stall the address bar.
- The browser accepts an initial address as its first argument. It made
  the smoke test scriptable and doubles as a launcher.
- Thirteen unmaintained advisories from the GTK3 bindings and Tauri's
  codegen are ignored in `deny.toml` with reasons. Tauri 2 has no GTK4
  path yet.

## Open for M4

- Compose has no preview and no pointer management beyond one name.
- Back navigation is an in-memory trail, not history.
- The blob view shows only images. Other blob kinds need a download
  affordance.
- The revocation effective time question carried from M1.
