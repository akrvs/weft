# M24

Status: planned
Started: 2026-09-22

## Goal

Fill the naming layer and give the reader a say in what they see. A
petname is the reader's own word for a key, typed in the address bar
before any domain. A label list is a labeler's signed statement about
records and keys; the browser subscribes to labelers and hides, blurs,
warns, or highlights what they label. Both are signed list records whose
head is a pointer, so they reuse the store, the relay, and the pull path
unchanged.

## Decisions

| Topic | Decision |
|---|---|
| Scope | Petnames and label lists together, CLI and browser. Gateway and relays ignore labels |
| Petname record | `kind = "petname"`, body `{ names: [ { key: bytes(32), name: text } ] }`, 0 to 512 entries sorted by `name`, names unique. A petname is 1 to 32 bytes, first `a-z`, then `a-z`, `0-9`, `-` |
| Label record | `kind = "label"`, body `{ labels: [ { key or record: bytes(32), value: text } ] }`, exactly one of `key` and `record`, `value` in the kind grammar, 0 to 512 entries sorted by canonical encoding, unique. A key label covers every record by that author. Values are open |
| Head | A list record is a whole snapshot. Its head is the author's pointer `petnames` or `labels`, the pointer rule. An empty list is how the last entry goes |
| Verify | Both kinds decode and check in `verify`; no authorization beyond section 7. Neither is reserved, so both are grantable |
| Privacy | Own petnames live in the home store and leave it only through `weft push`. Nothing publishes on change |
| Address bar | `Target::Petname { petname, name }`: a head with no dot that is not an address and fits the petname grammar, `name` defaulting to `home`. Resolves through the reader's own list head, local only, never pulled. An unknown petname is `Error::Petname`. Addresses are 60 characters, so a petname never parses as one, and a dot means a domain, so a petname never shadows DNS |
| Subscribed petnames | Import only. `weft petname import <key> [name]...` and a browser button copy entries from another list into the reader's own; existing names are kept and reported. No live fallback |
| Gateway | A petname target is 404; the operator's names are never served |
| Labels in the browser | `<home>/browser/labelers` (`<key address>` per line, at most 64) and `<home>/browser/actions` (`<value>\t<hide\|blur\|warn\|highlight>`), 0700 and 0600, rewritten whole. A page gathers hits on its record address and its author from each labeler's list head in the local store only; subscribing and a refresh button pull the heads. Strongest action wins: hide, blur, warn, highlight, then a plain badge for unmapped values |
| Petnames in the browser | The provenance panel shows the author's petname; a name field adds one. A Names view lists, adds, removes, and imports. Writes go over the existing socket: `put` of the list record, then `point` |
| Store socket | No new request. `put` already signs any non reserved kind for the browser key and granted apps; `point` stays browser only |
| CLI | `weft petname add <name> <key>`, `remove <name>`, `list [key]`, `import <key> [name]...`; `weft label add <address> <value>`, `remove <address> <value>`, `list [key]`. Each change writes a list record and its pointer, `--as` picks the signer, and prints both addresses for `weft push`. `list <key>` pulls |
| Dependencies | None new |

## Plan

1. Core: `petname.rs` and `label.rs` with check, encode, decode, draft,
   `from_record`; `verify` arms; vectors with every rejection; protocol
   sections.
2. Resolve: `Target::Petname` parse and display with negatives;
   `Resolver::petnames` over the own head offline, `labels(key)` over a
   labeler's head, `resolve` mapping a petname to `Named`.
3. CLI: petname and label commands through one list writer; e2e.
4. Gateway: petname target 404, test.
5. Browser: state files, page annotation, views, drive smoke with a
   petname opened from the bar and a labeled page warned and hidden;
   screenshots.
6. Close.

## Out of scope

- Label authoring in the browser; labelers publish from the CLI.
- Live fallback through other people's petname lists.
- Labels in the gateway or relays.
- Pointing by granted apps.
