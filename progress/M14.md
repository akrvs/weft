# M14

Status: planned
Started: 2026-09-08

## Goal

Gateway and relay operations. Close what M13 left open and the two "read
only at start" gotchas: a logged in reader pulls under a byte budget, the
in-flight cap is a flag, and both daemons reload their files on SIGHUP.
The demo: a reader logs in, pulls a page, is told the budget is spent on
the next miss while local pages still serve; an operator adds a root to
the gateway allow list and to the relay allow list, sends SIGHUP to each,
and the root logs in and pushes without a restart.

## Decisions

| Topic | Decision |
|---|---|
| Budget unit | Bytes per root identity in a fixed window: 64 MiB per hour by default, `--budget <MiB>`, 0 disables. Counted from the bytes the resolver hands to `keep` and `keep_blob`, so only relay pulls cost. All sessions of one identity share the counter. The window opens at the first charged byte and resets one hour later |
| Where the meter is | `Resolver::metered(counter)` returns a handle over the same shared state that adds to the counter at the two keep choke points. The gateway meters each logged in request and charges the identity after the route |
| Over budget | The request reads with `Resolver::offline`. Local records serve; a miss is 404 with `; pull budget spent, resets at <time>`. Never 429 for a local read |
| Pull cap flag | `--pulls <n>`, default 4, gateway wide in flight as before. 429 only past it |
| Reload | SIGHUP. Gateway rereads `--allow` and sweeps expired sessions to disk. Relay rereads `allow`, `banks`, `rate` and runs one sweep. A file that fails to parse logs to stderr and keeps the running config. Without `--allow` the gateway only sweeps |
| Relay config | `allow` and `pricing` move behind one `RwLock<Arc<Config>>` shared by every clone; a batch loads the config once so one push sees one set of rules |
| Dependencies | Nothing new. `tokio::signal::unix` from the workspace `signal` feature |

## Layout

```
crates/resolve/src/resolver.rs     meter, metered(), the two keep choke points
crates/resolve/tests/pull.rs       metered pull counts bytes, local read counts none
crates/gateway/src/budget.rs       Budget, window, charge, spent
crates/gateway/src/login.rs        allow behind a lock, set_allow, sweep
crates/gateway/src/lib.rs          budget in Gateway, hint plumbing, builders
crates/gateway/src/main.rs         --pulls, --budget, SIGHUP task
crates/gateway/tests/serve.rs      budget spent hint, allow reload takes effect
crates/net/src/relay.rs            Config, reload, config() per batch
crates/net/tests/relay.rs          reload lets an unlisted author push
crates/relay/src/main.rs           SIGHUP task rereads and sweeps
docs/relay.md, README.md           reload, flags, badges
```

## Plan

1. Resolver meter: `meter: Option<Arc<AtomicU64>>` on the handle,
   `metered()`, private `kept` and `kept_blob` wrapping the five call
   sites. Test: a pulled record and blob add their sizes, a local hit adds
   nothing, `offline()` of a metered handle keeps the meter.
2. Gateway budget: `budget.rs` with `Budget::new(bytes, window)`,
   `spent(author, now) -> Option<u64>` reset time when over, `charge`.
   Unit tests: under, over, window reset, zero disables. `read` checks
   before the route, meters, charges after. `route` takes the miss hint.
3. Gateway reload: `Logins.allow` in a `RwLock`, `set_allow`, `sweep(now)`
   that retains and saves. `Gateway::budget` builder, `--pulls`,
   `--budget`, SIGHUP task in `main`. Tests: a stranger is refused, the
   allow set is replaced, the stranger logs in; sweep drops an expired
   session from the file.
4. Relay reload: `Config { allow, pricing }` behind `RwLock<Arc<_>>`,
   `reload`, every handler reads `self.config()` once. SIGHUP task in
   `serve`. Test: unlisted author refused, reload, accepted; `price`
   reports the new rate.
5. Docs, README, smoke test the real binaries with `kill -HUP`, close.

## Out of scope

- A fake name server for the negative DNS path.
- Per session budgets on disk; counters reset with the process.
- Reload on any signal but SIGHUP, and file watching.
- Sponsorship and payments changes.
