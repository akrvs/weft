# M19

Status: in progress
Started: 2026-09-15

## Goal

Close the browser rows of `BACKLOG.md`, the only rows left. The browser
gets a visual design with light and dark themes and a real icon, a
compose preview and pointer management, persistent history and
bookmarks, a view and a save button for blobs that are not images, a
progress bar while a blob pulls, price and pay from compose, a `weft:`
URL handler on Linux, and a passphrase field that empties after a failed
start. The demo: a challenge page in Firefox opens weft-browser through
the registered handler; a paid page is published from compose after
seeing the relay's price; a name is repointed from the store view; a
large blob shows its bytes arriving and then a save button.

## Decisions

| Topic | Decision |
|---|---|
| History and bookmarks | Two newline separated files under `<home>/browser/`, directory 0700, files 0600: `history` holds `<unix>\t<target>`, newest last, adjacent duplicates dropped, capped at 1024 lines; `bookmarks` holds `<target>\t<title>`, one per target. Written whole through `fs::write_private`. Back and forward walk an in memory trail; the history and bookmark dialogs read the files |
| Pay from compose | Compose shows every relay's rate and banks from `price`, takes a voucher as text and a days field 1 to 366. The voucher text is base64url without padding of the 256 byte voucher, `Voucher::to_text` and `from_text` in `weft-core` over the login helper; `weft-bank mint` prints it beside writing `--out`. The daemon signs the receipt through a new browser only request `receipt { body }` whose body is the canonical receipt body, decoded and checked by `Receipt::decode`, signed by the daemon's key, returned unstored. The browser pushes manifest, page, pointer and receipt to the voucher's relay and `keep`s the receipt only after the relay stored it, as the CLI does |
| Pointer management | Two browser only requests: `names` returns the head pointer record of every name the root owns; `point { name, target }` signs the next pointer for `name` at a held, verified record and stores it. `publish` and `point` share one pointer drafting path. The store view lists names with head, seq and target; a repoint form takes a name and an address; compose's name field offers existing names |
| Compose preview | `preview { markdown }` renders through `weft_resolve::render` with `Links::WEFT` and returns the HTML and the title; the pane updates as the user types, debounced at 200 ms. Nothing is signed until the button |
| Blob view | `blob_view { address }` fetches the blob through the resolver and answers `size` and a sniffed `kind`: `image` for PNG, JPEG, GIF, WebP magic; `text` for valid UTF-8 up to 64 KiB; `binary` otherwise. Images render as before, text renders in a `pre`, binary shows size and hash with a save button. `save_blob` writes `<downloads>/<address>` with `create_new`, where downloads is `$XDG_DOWNLOAD_DIR`, then the `XDG_DOWNLOAD_DIR` line of `~/.config/user-dirs.dirs`, then `~/Downloads`; an existing file is an error, never overwritten |
| Progress | `Client::pull_blob` takes an `on_progress: &mut dyn FnMut(u64)` and reports the `Progress` items of the iroh-blobs downloader; the resolver carries an optional `Arc<dyn Fn(Address, u64) + Send + Sync>` set by `Resolver::watched`, emitted by the browser as the Tauri event `pull` with `address` and `done`. The total is not known before the transfer ends, so the bar is indeterminate with a byte count and closes when the page renders or fails. The gateway and CLI pass nothing |
| URL handler | `weft-browser register`, Linux only: writes `$XDG_DATA_HOME/applications/weft.desktop`, default `~/.local/share/applications`, with `Exec=<current exe> %u` and `MimeType=x-scheme-handler/weft;`, then runs `xdg-mime default weft.desktop x-scheme-handler/weft` and `update-desktop-database` when present. A second launch is a second process; both share the daemon through `browser.key`. Nothing is written without the command |
| Theme | Tokens on `:root`, dark values under `prefers-color-scheme: dark`, no toggle, nothing persisted. System font stack, monospace for addresses. The provenance panel is a single line that expands on click. Icon is an SVG drawn in the repo and rasterised once to `icons/icon.png`; Tauri embeds it as the window icon at build time |
| Passphrase | The start form empties the passphrase on failure as well as success |
| Dependencies | None added. `data-encoding` already in core, `gtk` already in the browser |

## Layout

```
crates/core/src/receipt.rs           Voucher::to_text, from_text
crates/bank/src/main.rs              mint prints the voucher text
crates/net/src/client.rs             pull_blob with a progress callback
crates/resolve/src/resolver.rs       watched, progress on pull
crates/store/src/wire.rs             names, point, receipt
crates/store/src/gate.rs             names, point, receipt over one pointer path
crates/store/src/server.rs           dispatch
crates/store/src/client.rs           names, point, receipt
crates/store/tests/gate.rs           positive and negative tests
crates/browser/src/main.rs           commands, register subcommand, events
crates/browser/src/marks.rs          history and bookmarks files
crates/browser/src/blobs.rs          sniff, downloads dir, save
crates/browser/src/register.rs       desktop file
crates/browser/icons/                icon.svg, icon.png
crates/browser/ui/                   index.html, style.css, src/main.ts
docs/store.md                        three requests
```

## Plan

1. Core and bank: voucher text form with tests; mint prints it.
2. Store: `names`, `point`, `receipt` in wire, gate, server, client,
   doc; tests for each rule and each rejection.
3. Net and resolve: progress callback through `pull_blob` and `watched`.
4. Browser back end: `marks`, `blobs`, `register` modules with tests;
   new commands `preview`, `price`, `publish` with voucher and days,
   `names`, `point`, `blob_view`, `save_blob`, `history`, `bookmarks`,
   `bookmark`, `unbookmark`; `pull` events; `register` subcommand.
5. Browser front end: new layout and stylesheet, provenance line,
   history and bookmarks dialogs, forward button, compose with preview,
   price and voucher, store view with names and repoint, blob panel,
   progress bar, passphrase reset.
6. Icon: draw, rasterise, verify the window shows it.
7. Smoke test the release binaries: register and open a `weft:login`
   link from Firefox, pay a relay from compose, repoint a name, pull a
   large blob and save it. Screenshot the browser in both themes.
8. Close: docs, README, handoff, backlog.

## Out of scope

- macOS and Windows URL handler registration.
- A single instance plugin.
- A theme toggle.
- Bookmarks as signed records.
- A native file dialog.
