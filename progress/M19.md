# M19

Status: complete, smoke tested on Linux with the release binaries
Started: 2026-09-15

## Goal

Close the browser rows of `BACKLOG.md`, the only rows left. The browser
gets a visual design with light and dark themes and a real icon, a
compose preview and pointer management, persistent history and
bookmarks, a view and a save button for blobs that are not images, a
progress bar while a blob pulls, price and pay from compose, a `weft:`
URL handler on Linux, and a passphrase field that empties after a failed
start. The demo: a challenge page in Firefox opens weft-browser through
the registered handler; a paid page is published from compose after
seeing the relay's price; a name is repointed from the store view; a
large blob shows its bytes arriving and then a save button.

## Decisions

| Topic | Decision |
|---|---|
| History and bookmarks | Two newline separated files under `<home>/browser/`, directory 0700, files 0600: `history` holds `<unix>\t<target>`, newest last, adjacent duplicates dropped, capped at 1024 lines; `bookmarks` holds `<target>\t<title>`, one per target. Written whole through `fs::replace_private`. Back and forward walk an in memory trail; the history and bookmark dialogs read the files |
| Pay from compose | Compose shows every relay's rate and banks from `price`, takes a voucher as text and a days field 1 to 366. The voucher text is base64url without padding of the 256 byte voucher, `Voucher::to_text` and `from_text` in `weft-core`; `weft-bank mint` prints it beside writing `--out`. The daemon signs the receipt through a new browser only request `receipt { body }` whose body is the canonical receipt body, decoded and checked by `Receipt::decode`, refused when `until` has passed, signed by the daemon's key, returned unstored. The browser pushes manifest, page, pointer and receipt to the voucher's relay and `keep`s the receipt only after the relay stored it, as the CLI does |
| Pointer management | Two browser only requests: `names` returns the head pointer record of every name the root owns, sorted by name; `point { name, target }` signs the next pointer for `name` at a held, verified record and stores it. `publish` and `point` share `next_pointer`. The store view lists names with seq and target; a repoint form takes a name and an address; compose's name field offers existing names |
| Compose preview | `preview { markdown }` renders through `weft_resolve::render` with `Links::WEFT` and returns the HTML and the title; the pane updates as the user types, debounced at 200 ms. Nothing is signed until the button |
| Blob view | `blob_view { address }` fetches the blob through the resolver and answers `size`, a sniffed `kind`, and the text when it is text: `image` for PNG, JPEG, GIF, WebP magic; `text` for valid UTF-8 up to 64 KiB without NUL; `binary` otherwise. Images render as before, text renders in a `pre`, binary shows size and hash with a save button. `save_blob` writes `<downloads>/<address>` with `create_new`, where downloads is `$XDG_DOWNLOAD_DIR`, then the `XDG_DOWNLOAD_DIR` line of `~/.config/user-dirs.dirs`, then `~/Downloads`; an existing file is an error, never overwritten |
| Progress | `Client::pull_blob` takes an `on_progress: &mut (dyn FnMut(u64) + Send)` fed by the `Progress` items of the iroh-blobs downloader; the resolver carries an optional `Watch`, `Arc<dyn Fn(Address, u64) + Send + Sync>`, set by `Resolver::watched`, emitted by the browser as the Tauri event `pull` with `address` and `done`. The total is not known before the transfer ends, so the bar is indeterminate with a byte count and closes when the page renders or fails. The gateway and CLI pass nothing |
| URL handler | `weft-browser register`, Linux only: writes `$XDG_DATA_HOME/applications/weft.desktop`, default `~/.local/share/applications`, with `Exec="<current exe>" %u` and `MimeType=x-scheme-handler/weft;`, installs the icon under `icons/hicolor/256x256/apps`, then runs `xdg-mime default weft.desktop x-scheme-handler/weft` and `update-desktop-database` when present. A second launch is a second process; both share the daemon through `browser.key`. Nothing is written without the command |
| Theme | Tokens on `:root`, dark values under `prefers-color-scheme: dark`, no toggle, nothing persisted. System font stack, monospace for addresses. The provenance panel is a single line that expands on click. Icon is `icons/icon.svg`, a warp and weft motif, rasterised once to `icons/icon.png`; Tauri embeds it as the window icon at build time |
| Passphrase | The start form empties the passphrase before the call, so a refusal leaves the field blank and focused |
| Dependencies | None added to the workspace. `futures-util`, already pinned, enters `weft-net` for the progress stream; `weft-net` enters `weft-browser` for `MAX_DAYS` and `PutOutcome` |

## Delivered

- `Voucher::to_text` and `from_text`; `weft-bank mint` prints the text
  under the address and the amount.
- Store requests `names`, `point`, `receipt`, browser only, documented in
  `store.md`, with tests for the head listing, the repoint chain, the
  refusal of an unknown target, the unstored signed receipt, an expired
  or mismatched receipt, a foreign key, and the wire limits.
- `Client::pull_blob` reports pulled bytes; `Resolver::watched` forwards
  them per address; the pull test asserts monotone counts ending at the
  blob length.
- Browser modules `marks`, `blobs`, `register` with unit tests for the
  cap, the dedup, the permissions, the field rules, the sniff table, the
  downloads lookup order, the `create_new` refusal, and the desktop entry.
- Browser commands for preview, price, paid publish, names, point, blob
  view, save, history, bookmarks; `pull` events; `weft-browser register`.
- A new stylesheet with light and dark tokens, a one line provenance
  panel with details on click, back and forward, a bookmark button,
  history and bookmarks dialogs, a two pane compose with live preview,
  a price table and a voucher field, a names table and repoint form in
  the store dialog, a blob panel with a save button, a pull bar, and a
  passphrase field that empties before every attempt.
- An icon drawn as SVG and rasterised to PNG, embedded as the window icon
  and installed by `register`.

## Deviations from the plan

- The history file is written through `replace_private`, not
  `write_private`, since the latter refuses an existing file.
- `blob_view` also carries the text of a text blob, so the page never
  fetches `weft://blob/` for anything but images; the CSP allows no
  fetch from the chrome.
- `futures-util` was added to `weft-net` and `weft-net` to
  `weft-browser`; the plan said no dependency changes. Both are workspace
  crates or pins already present.
- The smoke test drove the browser through its command line argument only:
  the home page pulled from the relay, the 3 MB blob pulled and kept with
  the save panel shown, and a gateway login challenge opening the consent
  dialog. Compose, pay, repoint, history, and bookmark dialogs were not
  clicked, `/dev/uinput` being root only here; their logic is covered by
  the store and module tests. The light palette was not seen; WebKitGTK
  followed the portal's dark setting. Both are in `BACKLOG.md`.
- `register` was verified against `XDG_DATA_HOME` and `XDG_CONFIG_HOME`
  pointed at a scratch directory, not the user's own.
