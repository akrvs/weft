# M10

Status: complete, smoke tested on Linux with screenshots
Started: 2026-09-08

## Goal

Harden the store as a daemon the browser can live with for a long
session. The record cache and the verification memo stop growing past
the directory they mirror. Browser requests to the daemon run in
parallel over a small pool instead of one serialized socket. The
attached daemon's stderr is drained into a bounded log that the store
dialog shows, so a chatty daemon never blocks on a full pipe. A
navigation that finds no daemon opens the start form directly and
retries once the daemon is up. The browser key is fresh on every daemon
start, so a leaked key is good for one run only. The demo: start the
browser cold, type an address, start the daemon from the form the
failure opens, watch the page render, and see the daemon's log in the
store dialog.

## Decisions

| Topic | Decision |
|---|---|
| Eviction | `Store::snapshot` mirrors the directory: cached records whose file is gone are dropped, and memo entries whose manifest hash is not among the manifests still on disk are dropped. Memory is bounded by the store. No cap constant, no dependency |
| Local pool | `Local` keeps up to 4 idle `Client`s behind a mutex. A call takes an idle one or connects, returns it on success, drops it on failure. A reused connection that fails with an IO or wire error retries once on a fresh one, as before |
| Stderr | The browser spawns the daemon with stderr piped and a thread drains it into a ring of the last 16 KiB held in `App`. A failed start reports that text. The store dialog shows it under the tables and refreshes it on open |
| Failed navigation | A `resolve` error that names the missing daemon opens the store dialog with the start form; a successful start reruns the navigation that failed |
| Key rotation | `weft-store serve` writes a fresh `browser.key` on every start, through a temp file and rename, both mode 0600. `Local` reads the key at connect, so the browser follows a restart. A handshake refused for a stale key drops the connection and the next call rereads the key |
| Directory creation | Already handled: `fs::write` creates the parent. The M4 backlog row is stale and goes |
| Dependencies | Nothing new |

## Plan

1. Home: `snapshot` prunes the record cache and the memo to what the listing saw. Test: a deleted file leaves the cache, an old manifest leaves the memo.
2. Home fs: `replace_private` writes a temp file mode 0600 and renames. Gate: `create_browser_key` uses it. Daemon: always create. Test: the key differs across two starts, a client holding the old key is refused, `Local` recovers.
3. Local: pool of 4. Test: concurrent calls complete and a daemon restart is survived.
4. Browser: drain thread, `daemon_log` command, dialog shows the log, failed navigation opens the form and retries.
5. Docs, smoke test with screenshots, close.

## Delivered

- `Store::snapshot` prunes the record cache and the verification memo to
  the files and manifests the listing saw. A deleted record leaves the
  cache on the next snapshot.
- `weft_home::fs::replace_private` writes through a temp file and
  renames; `create_browser_key` uses it and `weft-store serve` writes a
  fresh key on every start, after it holds the socket.
- `weft_store::serve` owns its connection tasks in a `JoinSet`, so a
  serve future that ends takes its connections with it.
- `Local` keeps up to four idle connections; concurrent browser requests
  no longer wait on one socket.
- Browser: the daemon's stderr is drained into a 16 KiB ring, a failed
  start reports it, `daemon_log` shows it in the store dialog. A
  navigation with the daemon down opens the start form and reruns once
  the daemon is up.
- Tests: 77 passing, 1 new plus 2 extended. Smoke test on Linux: cold
  browser, address typed, start form opens, wrong passphrase reports the
  daemon's error through the drain, right passphrase renders the page,
  `browser.key` hash differs from the previous run, store dialog shows
  the daemon log for a device outside the manifest, closing the browser
  ends the daemon and removes the socket.

## Deviations from the plan

- `serve` gained a `JoinSet` so the test restart closes connections the
  way a process exit does. Without it aborting the accept loop left
  connections alive and the pool test could not see a restart.
- The memo prune is exercised through the same `retain` call as the
  record prune; there is no observable memo count, so it has no
  assertion of its own.

## Open for M11

- The cache mirrors the directory, so a store larger than memory has no
  cap.
- The start form keeps a refused passphrase in the field.
- The gateway still reads the directory.

## Out of scope

- Store index on disk.
- Detached daemon.
- Grants over fetched records, application display names.
- Gateway behind the daemon.
